                    PARTICIPANT BRIEF                     SeptiSense • IoT-Enabled Predictive Patient Monitoring                                                             Team format and participation details: Refer to the event instructions.                          The challenge            Develop an integrated patient-monitoring and early-warning system that combines embedded hardware, physiological sensing, machine learning, and web technologies. The system should collect physiological measurements, transmit telemetry to a laptop-based processing system, estimate future sepsis-related risk using a trained ML model, and present measurements and predictions through an interactive dashboard.             Problem overview            Sepsis can lead to organ dysfunction and requires timely medical attention. SeptiSense focuses on the challenge of identifying early signs of patient deterioration through continuous physiological monitoring. The objective is to develop an educational and research prototype that demonstrates how physiological data and machine learning can support early identification of potential deterioration.                                            Acquire available physiological measurements, including ECG signals, heart rate, SpO₂, and temperature.                                            Transmit timestamped sensor telemetry from the embedded node to a laptop-based processing system.                                            Use a trained ML model and an appropriate clinical dataset to estimate the likelihood of a future sepsis-related outcome.                                            Display current measurements, historical trends, model-generated predictions, and alerts through a web dashboard.                                            Maintain patient telemetry history and alert records, and show device connectivity and data-quality status.            The prototype is for educational and research purposes and must not be represented as a clinically validated diagnostic system. Embedded Systems and IoT            The embedded monitoring node is responsible for physiological data acquisition, basic signal processing, timestamping, and telemetry transmission. The implementation should consider:                                            Acquiring physiological measurements using the available compatible sensors.                                            Applying basic signal processing and validating sensor data.                                            Handling missing measurements and communication interruptions; temporary offline buffering may be implemented where appropriate.                                            Transmitting reliable, timestamped telemetry to the laptop-based processing system.             Artificial Intelligence and Machine Learning                                            Select an appropriate, legally accessible clinical dataset relevant to the chosen sepsis-related prediction target.                                            Define the prediction target and forecast horizon clearly, based on the selected dataset and evaluation.                                            Analyze historical patient data and time-series physiological measurements to estimate a future outcome.                                            Document model evaluation using a held-out dataset, suitable metrics, and precautions against class imbalance and data leakage.             Web Development            Develop an interactive dashboard integrated with the telemetry backend and ML inference service. It should present current patient measurements, historical trends, future-risk estimates and prediction horizons, configurable alert notifications, alert history, and sensor connectivity/data-quality status.             System architecture and data flow                                            Embedded monitoring node: ESP8266 NodeMCU or ESP32-S3 with compatible sensors for data acquisition, basic processing, timestamping, telemetry transmission, and local alerts.                                            Laptop-based processing system: receives and stores telemetry, manages historical data, runs ML inference, manages predictions and alerts, and provides backend API services.                                            Web dashboard: presents real-time monitoring, historical measurements, future-risk estimates, alert history, and device connectivity.                                            Data flow: Physiological sensors → Embedded node (Wi-Fi) → Laptop backend and ML inference → Web dashboard.                                            A Raspberry Pi is not required. The laptop is the centralized processing system.             Machine learning and software requirements                                            Choose a suitable clinical dataset, such as a relevant PhysioNet sepsis dataset, MIMIC-IV (subject to access requirements), or another appropriate and legally accessible source.                                            Clearly document the prediction target, forecast horizon, and evaluation methodology.                                            Evaluate the model on held-out data using appropriate metrics such as AUROC, AUPRC, sensitivity, specificity, precision, recall, and calibration, as relevant.                                            Integrate the trained model with the backend so predictions can be generated from the available data.                                            Integrate telemetry, model inference, data storage, and dashboard visualization into a functional prototype.                                              Important note  The prototype is intended for educational and research purposes; it must not be represented as a clinically validated diagnostic system.
